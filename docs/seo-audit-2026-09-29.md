## Verification

**Pre-change production:** all 29 sitemap pages returned 200 with matching canonical URLs, a title/description, one H1 and parseable JSON-LD. All 82 additional internal routes/assets checked returned 200, including 18 distinct image-sitemap images. robots.txt and both sitemaps are reachable. HTTPS certificates verified normally; HTTP and www redirect to HTTPS apex, although HTTP www takes two hops. Unknown URLs return 404 with `noindex, follow`. HTML is gzip compressed and revalidated; asset caching is long-lived.

**Local source checks:** `python3 scripts/seo-check.py` passes for 31 HTML files, 29 canonical sitemap pages, 956 local references, and 28 JSON-LD blocks. All sitemap pages are reachable from the homepage through static links within two clicks. It checks unique titles/descriptions, canonical/social URLs, headings, image alt presence, links/fragments, sitemaps and JSON syntax. The nonpublic article template deliberately contains authoring placeholders. `node --check script.js`, `node --check script.min.js` and `git diff --check` pass. These checks do not establish Google rich-result eligibility.

**Local browser checks:** an isolated headless Brave browser checked the homepage, Barrie page, blog index and Barrie wedding article at 1440px, 390px and 320px. The initial samples produced no JavaScript exceptions, HTTP errors or network failures. All 14 article cards remained accessible with JavaScript disabled. Mobile homepage loads requested no videos. Local unthrottled LCP samples were roughly 0.05–0.16 seconds; these values reflect localhost and must not be reported as production speed. The original desktop homepage repeatedly showed CLS 0.132: its hero changed size as asynchronously loaded styles applied. Making the main stylesheet render-blocking reduced CLS to 0.000818 (about 0.001) in the final cache-disabled local desktop check, with LCP 236ms; the final 320px check had CLS 0, LCP 192ms, and no video requests. Both had no JavaScript/network/HTTP errors. These are local unthrottled diagnostics, not field Core Web Vitals or production speed claims. Production throttled tests and Search Console field data are still needed.

The 320px checks exposed a clipped Barrie booking button and enlarged-text card overflow. The targeted recheck confirmed the CSS fixes keep the Barrie hero/button and affected enlarged-text home/blog cards within the viewport. Text enlargement used a 200% root font size, not browser zoom. Existing fixed navigation and bottom contact bars still occupy excessive space with enlarged text; a complete accessibility pass is outstanding.

CSS/JS URLs have been versioned as `20260929-seo` to avoid stale long-lived bundles. The sitemap modification dates identify substantively updated pages. No deployed behavior of the new code is claimed.
